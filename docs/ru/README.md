# Raptor

**Высокопроизводительное in-memory хранилище ключ-значение, написанное на Rust**

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](https://opensource.org/licenses/MIT)
[![Rust](https://img.shields.io/badge/rust-1.89+-000000.svg)](https://www.rust-lang.org/)

Raptor - это высокопроизводительное in-memory хранилище структур данных, написанное на Rust. Оно поддерживает все основные типы данных с акцентом на производительность, надежность и современную архитектуру программного обеспечения.

## 🚀 Возможности

### Структуры данных
- **Строки** - Базовые строковые значения с бинарной безопасностью
- **Хэши** - Карты поле-значение внутри ключей
- **Списки** - Упорядоченные коллекции с операциями push/pop
- **Множества** - Неупорядоченные уникальные коллекции
- **Отсортированные множества** - Упорядоченные множества с оценками
- **TTL (Time-To-Live)** - Автоматическое истечение срока действия ключей
- **Массивы** - Динамические массивы с операциями индексации

### Производительность и надежность
- **Высокая производительность** - Оптимизировано для конкурентных нагрузок с использованием DashMap
- **Умный LRU кэш** - Интеллектуальное управление памятью с учетом TTL и приоритизацией по оценкам
- **Снапшоты** - Постоянное хранение с настраиваемыми интервалами
- **Graceful Shutdown** - Чистое завершение с сохранением финального снапшота
- **Комплексные бенчмарки** - Обширный набор тестов производительности

### Опыт разработчика
- **Чистая архитектура** - Гексагональная архитектура с четким разделением ответственности
- **Async/Await** - Современное асинхронное программирование
- **Комплексное тестирование** - Unit, интеграционные и E2E тесты
- **Поддержка Docker** - Готовый к развертыванию контейнер

# Запуск в Docker

```bash
# Сборка и запуск с Docker
docker-compose up --build

# Или запуск напрямую
docker run -p 3000:3000 raptor
```

## 🔧 Конфигурация

Raptor может быть настроен через переменные окружения:

| Переменная | По умолчанию | Описание |
|------------|--------------|----------|
| `PORT` | `3000` | Порт HTTP сервера |
| `LOG_FORMAT` | `json` | Формат логов (json/text) |
| `MAX_MEMORY_BYTES` | `RAM системы * 0.9` | Лимит памяти для LRU |
| `SNAPSHOT_INTERVAL_SECONDS` | `10` | Интервал снапшотов |
| `SMART_LRU_EVICTION_THRESHOLD` | `0.8` | Порог памяти для умного выселения (0.1-0.95) |
| `SMART_LRU_CHECK_INTERVAL_SECONDS` | `30` | Интервал между проверками памяти |
| `SMART_LRU_MIN_EVICTION_RATIO` | `0.05` | Мин. записей для выселения (0.01-0.5) |
| `SMART_LRU_MAX_EVICTION_RATIO` | `0.2` | Макс. записей для выселения (0.05-0.8) |
| `SMART_LRU_TTL_WEIGHT` | `0.4` | Вес приоритета TTL (0.0-1.0) |
| `SMART_LRU_ACCESS_WEIGHT` | `0.4` | Вес приоритета времени доступа (0.0-1.0) |
| `SMART_LRU_SIZE_WEIGHT` | `0.2` | Вес приоритета размера (0.0-1.0) |
| `FEATURE_INCR_COMMAND` | `true` | Включить команду INCR |

## 🎯 Примеры использования

### Базовые операции
```bash
# Установить ключ
curl -X POST "http://localhost:3000/single_key/set/mykey" \
  -H "Content-Type: application/json" \
  -d '{"value": {"type": "String", "value": "SGVsbG8gV29ybGQ="}}'

# Получить ключ
curl "http://localhost:3000/single_key/get/mykey"

# Удалить ключ
curl -X DELETE "http://localhost:3000/single_key/delete/mykey"
```

### Операции с хэшами
```bash
# Установить поле хэша
curl -X POST "http://localhost:3000/hash/hset/myhash/myfield" \
  -H "Content-Type: application/octet-stream" \
  -d "SGVsbG8="

# Получить поле хэша
curl "http://localhost:3000/hash/hget/myhash/myfield"
```

### Операции со списками
```bash
# Добавить в список
curl -X POST "http://localhost:3000/list/lpush/mylist" \
  -H "Content-Type: application/json" \
  -d '{"values": ["aXRlbTE=", "aXRlbTI="]}'

# Получить диапазон списка
curl -X POST "http://localhost:3000/list/lrange/mylist" \
  -H "Content-Type: application/json" \
  -d '{"start": 0, "stop": -1}'
```

### Операции с TTL
```bash
# Установить с TTL
curl -X POST "http://localhost:3000/single_key/set/key_with_ttl" \
  -H "Content-Type: application/json" \
  -d '{"value": {"type": "String", "value": "RXhwaXJpbmc="}, "ttl_seconds": 300}'

# Проверить TTL
curl "http://localhost:3000/single_key/ttl/key_with_ttl"

# Удалить TTL
curl -X POST "http://localhost:3000/single_key/persist/key_with_ttl"
```

## 📚 Типы данных и Base64 кодирование

**Важно:** Все бинарные данные должны быть закодированы в base64 в JSON запросах. API возвращает данные, закодированные в base64.

### Поддерживаемые типы
- `String` - Бинарно-безопасные строки
- `Integer` - 64-битные целые числа (возвращаются как base64-кодированные строки)
- `Hash` - Карты поле-значение
- `List` - Упорядоченные массивы
- `Set` - Множества уникальных значений
- `SortedSet` - Отсортированные по оценкам множества
- `Array` - Динамические массивы
